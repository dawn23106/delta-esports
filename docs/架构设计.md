## 后端分层

```
Controller → Service → Mapper (MyBatis) → MySQL
                ↓
           Redis (防重复/Token缓存)
```

- **Controller**: 参数校验、JWT 角色校验、调用 Service
- **Service**: 业务逻辑、状态流转校验、乐观锁
- **Mapper**: MyBatis 注解 + 动态 SQL
- **JwtAuthFilter**: 拦截 /api/*，解析 JWT 注入 userId/role

## 关键设计决策

### 乐观锁接单
打手抢单时使用 `UPDATE ... WHERE status='pending'` 的乐观锁，防止多人同时接同一单。

### Redis 防重复
同一用户 + 同一游戏 5 秒内只允许下一次单，Redis `SETNX` 实现。

### JWT 双 Token
- Access Token: 15 分钟，每次请求携带
- Refresh Token: 7 天，存 Redis，用于刷新 Access Token

### 角色权限
- player: 下单、看自己的订单
- booster: 浏览订单池、接单、开始/完成订单
- cs: 全量管理、手动创建/派单、取消任意订单、管理用户角色
