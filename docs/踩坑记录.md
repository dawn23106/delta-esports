## 二、按层分包结构

```
com.delta/
├── controller/    ← 接收HTTP请求，调用Service
│   ├── AuthController       注册/登录/刷新Token
│   ├── UserController       GET /me
│   ├── OrderController      玩家下单、打手接单/开始/完成
│   └── AdminController      客服：全量管理、派单、设角色
├── service/       ← 业务逻辑
│   ├── AuthService          BCrypt加密、JWT签发、Redis缓存RefreshToken
│   └── OrderService         状态流转、乐观锁抢单、敏感词过滤、防重复
├── mapper/        ← 数据访问（MyBatis XML方式）
│   ├── UserMapper.java      → resources/mapper/UserMapper.xml
│   └── OrderMapper.java     → resources/mapper/OrderMapper.xml
├── entity/        ← 数据库实体
│   ├── User                 用户表
│   └── Order                订单表（含service_type/source_channel）
├── security/      ← 安全
│   ├── JwtUtil              JWT生成/解析（jjwt 0.12）
│   └── JwtAuthFilter        HTTP过滤器，拦截/api/*校验Token
├── config/        ← Spring配置
│   ├── CorsConfig           跨域
│   ├── FilterConfig         注册JWT过滤器
│   ├── JwtProperties        读取yml中的jwt配置
│   └── DataInitializer      启动时自动创建客服账号
└── common/        ← 通用
    ├── Result/PageResult    统一响应格式
    ├── ErrorCode            错误码枚举
    ├── BusinessException    业务异常
    ├── GlobalExceptionHandler 全局异常处理
    └── SensitiveWordFilter  敏感词过滤
```

## 三、数据库设计

```sql
-- users 表
id, phone, password(bcrypt), nickname, role(player/booster/cs),
balance, is_active, created_at, updated_at

-- orders 表
id, game, service_type(tech/entertain/quest), detail, price,
status(pending/assigned/in_progress/completed/cancelled),
customer_id, booster_id, cs_id, source_channel, created_at, updated_at
```

**索引**: idx_orders_status, idx_orders_customer, idx_orders_booster, idx_orders_status_game

## 四、订单状态流转

```
玩家下单 → pending(待接单)
              ↓
           打手抢单（乐观锁: UPDATE WHERE status='pending'）
              ↓
         assigned(已接单)
              ↓
           打手点开始
              ↓
         in_progress(进行中)
              ↓
           打手点完成
              ↓
         completed(已完成)
         
任意非终态 → cancelled（玩家或客服取消）
```

**超时机制**: 订单创建后30分钟无人接单 → Redis延迟队列自动取消

## 五、核心功能清单

| 功能 | 实现方式 |
|------|----------|
| 手机号注册/登录 | BCrypt加密 + JWT双Token（Access 15m + Refresh 7d） |
| 防重复下单 | Redis SETNX 5秒幂等锁 |
| 抢单乐观锁 | MyBatis `UPDATE WHERE status='pending'`，affected=0则已被抢 |
| 敏感词过滤 | SensitiveWordFilter，含飞单/外挂/赌博等关键词 |
| 订单超时取消 | Redis key 30分钟TTL，到期自动取消 |
| 角色权限 | JWT中存role，AdminController校验cs角色 |
| 客服派单 | 跳过抢单环节，直接assign给指定打手 |
| 用户设角色 | 后台管理页，cs可把player升为booster |
| 获客渠道追踪 | Order.source_channel字段，埋点统计 |
| 服务分类定价 | Order.service_type支持技术/娱乐/任务三类 |

## 六、排查过的问题（按时间顺序）

### 1. Lombok 不兼容 JDK 24
**现象**: 编译报 `找不到符号: 方法 getXxx()`
**原因**: Lombok 1.18.34 不支持 JDK 24
**解决**: 全部删掉 Lombok，手写 getter/setter。IDEA Alt+Insert 自动生成。

### 2. 端口 3306 被占用
**现象**: Docker MySQL 起不来，`port 3306 already in use`
**原因**: 本机已装 MySQL 8.0 占用 3306
**解决**: docker-compose 改端口映射 `3307:3306`，application.yml 同步。后来完全不用 Docker。

### 3. GitHub DNS 劫持
**现象**: `curl github.com` 连接 127.0.0.1
**原因**: hosts 文件里 Steam++ 把 GitHub 全屏蔽了
**解决**: 管理员记事本删掉 `# Steam++ Start` 到 `# Steam++ End` 之间所有行

### 4. Redis 启动失败 → 后端 500
**现象**: 后端登录报 `服务器繁忙，请稍后重试`
**原因**: 第一次 Redis 没装，Spring Boot 尝试连 Redis 失败
**解决**: ①排除 Redis 自动配置 ②把 Redis 依赖改为可选（@Autowired(required=false)）③下载 Redis for Windows ④恢复配置
**学到的**: 外部依赖一定要做降级处理

### 5. GitHub 加速器只代理浏览器
**现象**: VPN 开了但 `curl github.com` 还是不通
**原因**: 国内加速器通常是浏览器代理或 TUN 模式，命令行不自动走代理
**解决**: curl 加 `-k` 跳过 SSL 验证（Windows schannel 兼容问题）

### 6. 前端"网络错误"
三次排查：
- **第一次**: Docker Desktop 没启动 → Redis 连不上 → 后端 500
- **第二次**: 前端 dev server 没启动
- **第三次**: `vite.config.js`（脚手架生成，无代理配置）覆盖了 `vite.config.ts`（有代理配置），导致 API 请求 404
**解决**: 删掉 `vite.config.js`，只用 `.ts` 版本
**学到的**: Vite 脚手架同时生成 `.js` 和用户写的 `.ts` 时，`.js` 优先

### 7. 手机号校验拦截客服账号
**现象**: 客服 `00000000000` 登录报"手机号格式错误"
**原因**: 正则 `^1[3-9]\d{9}$` 不匹配 00000000000
**解决**: 客服手机号改为 `13800000000`

### 8. Mapper 注解与 XML 混用冲突
**现象**: `Mapped Statements collection already contains key`
**原因**: `insert` 方法同时在 @Insert 注解和 XML 里定义了
**解决**: 统一用 XML 方式，接口只保留方法声明

## 七、MyBatis XML 方式要点

1. 接口只声明方法，不加 SQL 注解
2. XML 文件的 namespace 必须指向完整接口路径 `com.delta.mapper.UserMapper`
3. resultMap 中的 column 是数据库字段名，property 是 Java 属性名
4. 动态 SQL 用 `<if test="条件">SQL片段</if>`
5. `<where>` 标签自动处理第一个 AND
6. INSERT 的 `useGeneratedKeys="true" keyProperty="id"` 实现自增主键回填
