## 一、Spring Boot 核心

### 1.1 项目初始化与配置

#### @SpringBootApplication
启动类注解，等于 `@Configuration` + `@EnableAutoConfiguration` + `@ComponentScan` 三个注解的组合。
- `@ComponentScan`: 扫描当前包及子包下的 `@Component`、`@Service`、`@Controller` 等
- `@EnableAutoConfiguration`: 根据 classpath 中的 jar 自动配置（如检测到 MySQL 驱动就配数据源）

#### application.yml 配置
```yaml
server:
  port: 8080                    # 服务端口

spring:
  datasource:                   # 数据源配置
    url: jdbc:mysql://localhost:3307/delta_helper?useSSL=false&serverTimezone=Asia/Shanghai
    username: root
    password: root
  data:
    redis:                      # Redis 配置
      host: localhost
      port: 6379

mybatis:
  mapper-locations: classpath:mapper/*.xml    # XML Mapper 路径
  configuration:
    map-underscore-to-camel-case: true        # 自动驼峰转换 (user_id → userId)

jwt:                            # 自定义配置 (通过 @ConfigurationProperties 读取)
  access-secret: xxx
  access-ttl: 15m
  refresh-secret: xxx
  refresh-ttl: 7d
```

#### @ConfigurationProperties
将 YAML 中以 `jwt` 开头的配置自动映射到 Java 对象的属性：

### 1.4 Filter（过滤器）

JWT 认证过滤器在请求到达 Controller 之前校验 token：

```java
@Component
public class JwtAuthFilter extends HttpFilter {

    private static final List<String> WHITELIST = List.of(
        "/api/auth/login", "/api/auth/register", "/api/auth/refresh"
    );

    @Override
    protected void doFilter(HttpServletRequest req, HttpServletResponse res, FilterChain chain) {
        // 1. 白名单放行
        if (WHITELIST.contains(req.getRequestURI())) {
            chain.doFilter(req, res);
            return;
        }
        // 2. 提取 Authorization: Bearer <token>
        String header = req.getHeader("Authorization");
        // 3. 解析 JWT, 把 userId 和 role 注入 request
        Claims claims = jwtUtil.parseAccessToken(header.substring(7));
        req.setAttribute("userId", Long.parseLong(claims.getSubject()));
        req.setAttribute("role", claims.get("role"));
        chain.doFilter(req, res);
    }
}
```

通过 `FilterRegistrationBean` 控制拦截路径：
```java
@Bean
public FilterRegistrationBean<JwtAuthFilter> jwtFilter(JwtAuthFilter filter) {
    FilterRegistrationBean<JwtAuthFilter> reg = new FilterRegistrationBean<>();
    reg.setFilter(filter);
    reg.addUrlPatterns("/api/*");       // 只拦截 /api 下的接口
    return reg;
}
```

## 三、JWT 认证

### 3.1 双 Token 机制

| Token | 有效期 | 存储 | 用途 |
|-------|--------|------|------|
| Access Token | 15分钟 | 客户端内存/localStorage | 每次请求带在 Header |
| Refresh Token | 7天 | localStorage + Redis | 刷新 Access Token |

为什么不只用一个大 TTL 的 Token？Access Token 泄露后 15 分钟就失效，减小攻击窗口。Refresh Token 存在 Redis 中，可随时作废。

### 3.2 JWT 生成 (jjwt 0.12)

```java
public String generateAccessToken(Long userId, String role) {
    SecretKey key = Keys.hmacShaKeyFor(secret.getBytes(StandardCharsets.UTF_8));

    return Jwts.builder()
        .claims(Map.of("role", role))                         // 自定义字段
        .subject(String.valueOf(userId))                      // 主题=用户ID
        .issuedAt(new Date())                                 // 签发时间
        .expiration(new Date(System.currentTimeMillis() + ttlMs))  // 过期时间
        .signWith(key)                                        // 签名
        .compact();
}
```

### 3.3 JWT 解析

```java
public Claims parseAccessToken(String token) {
    SecretKey key = Keys.hmacShaKeyFor(secret.getBytes(StandardCharsets.UTF_8));
    return Jwts.parser()
        .verifyWith(key)
        .build()
        .parseSignedClaims(token)
        .getPayload();
}

// 使用
Claims claims = jwtUtil.parseAccessToken(token);
Long userId = Long.parseLong(claims.getSubject());   // sub → userId
String role = (String) claims.get("role");           // 自定义字段
```

### 3.4 TTL 格式解析

支持 `15m`、`7d`、`1h` 等人类可读格式，转换成毫秒：
```java
private long parseTtl(String ttl) {
    char unit = ttl.charAt(ttl.length() - 1);  // m/d/h/s
    long num = Long.parseLong(ttl.substring(0, ttl.length() - 1));
    return switch (unit) {
        case 'm' -> num * 60 * 1000L;          // 分钟→毫秒
        case 'd' -> num * 86400 * 1000L;        // 天→毫秒
        case 'h' -> num * 3600 * 1000L;          // 小时→毫秒
        default -> num;
    };
}
```

### 4.2 防重复下单（SETNX 分布式锁）

```java
String lockKey = "order:lock:" + customerId + ":" + game;
// setIfAbsent = SETNX: 只有 key 不存在时才 set 成功，返回 true
Boolean locked = redis.opsForValue().setIfAbsent(lockKey, "1", Duration.ofSeconds(5));
if (locked == null || !locked) {
    throw new BusinessException(ErrorCode.BAD_REQUEST, "操作过于频繁，请5秒后再试");
}
```

原理：同一用户+同一游戏，5秒内只能下一次单。key 5秒后自动过期，不会永久锁住。

### 4.3 Refresh Token 存储

```java
// 登录时存
redis.opsForValue().set("refresh:" + userId, refreshToken, Duration.ofDays(7));

// 刷新时校验
String cached = redis.opsForValue().get("refresh:" + userId);
if (!refreshToken.equals(cached)) {
    throw new BusinessException(ErrorCode.UNAUTHORIZED, "token已失效");
}

// 登出时删除
redis.delete("refresh:" + userId);
```

## 五、数据库设计

### 5.1 建表 SQL

```sql
CREATE TABLE users (
    id BIGINT AUTO_INCREMENT PRIMARY KEY,
    phone VARCHAR(16) NOT NULL UNIQUE,
    password VARCHAR(128) NOT NULL,
    nickname VARCHAR(32),
    role VARCHAR(20) NOT NULL DEFAULT 'player',      -- player / booster / cs
    balance DECIMAL(10,2) NOT NULL DEFAULT 0,
    is_active BOOLEAN NOT NULL DEFAULT TRUE,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
) ENGINE=InnoDB;

CREATE TABLE orders (
    id BIGINT AUTO_INCREMENT PRIMARY KEY,
    game VARCHAR(64) NOT NULL,
    detail VARCHAR(128),
    price DECIMAL(10,2) NOT NULL,
    status VARCHAR(20) NOT NULL DEFAULT 'pending',    -- pending/assigned/in_progress/completed/cancelled
    customer_id BIGINT NOT NULL,                      -- 玩家
    booster_id BIGINT,                                -- 打手
    cs_id BIGINT,                                     -- 客服
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    INDEX idx_orders_status (status),
    INDEX idx_orders_customer (customer_id),
    INDEX idx_orders_booster (booster_id),
    INDEX idx_orders_status_game (status, game)       -- 复合索引: 订单池查询
) ENGINE=InnoDB;
```

### 5.2 索引设计思路

| 索引 | 对应查询 |
|------|----------|
| `idx_orders_status` | `WHERE status = 'pending'` — 订单池 |
| `idx_orders_customer` | `WHERE customer_id = ?` — 我的订单 |
| `idx_orders_booster` | `WHERE booster_id = ?` — 打手接单列表 |
| `idx_orders_status_game` | `WHERE status = 'pending' AND game = '三角洲'` — 按游戏筛选订单池 |

### 5.3 订单状态流转

```
pending ────→ assigned ────→ in_progress ────→ completed
   │              │               │
   └── cancelled ←┘────── cancelled ←──────────┘
```

Service 层用 if 判断控制状态流转，不合法时抛异常。

## 十、排查过的问题

### 问题1: Lombok + JDK 24 不兼容
**现象**: 编译时报 `找不到符号: 方法 getXxx()`
**原因**: Lombok 1.18.34 及以下版本不支持 JDK 24
**解决**: 移除 Lombok，手写 getter/setter。IDEA 可以 Alt+Insert 自动生成。

### 问题2: 端口被占用
**现象**: `ports are not available: exposing port TCP 0.0.0.0:3306`
**原因**: 本机已安装 MySQL 占用了 3306 端口
**解决**: docker-compose 改端口映射 `"3307:3306"`，application.yml 同步改。

### 问题3: 手机号校验拦截客服账号
**现象**: 客服登录报"手机号格式错误"
**原因**: 客服账号手机号 `00000000000` 不符合正则 `^1[3-9]\d{9}$`
**解决**: 改为合法手机号 `13800000000`

### 问题4: Vite 脚手架生成 main.js 而非 main.ts
**现象**: Build 报 `src/main.js is imported but missing`
**原因**: 新版本 Vite 脚手架模板生成的是 `.js` 文件
**解决**: 手动改 `index.html` 中的引用路径为 `/src/main.ts`

## 十一、面试可能问到的问题

### Q: 如何防止多人同时接同一单？
**A**: 乐观锁。`UPDATE orders SET booster_id=?, status='assigned' WHERE id=? AND status='pending'`。利用 MySQL 行锁，只有 status 还是 pending 时才能更新成功。如果 affected rows = 0，说明被抢了，返回错误给客户端。

### Q: 如何防止用户重复下单？
**A**: Redis SETNX。`SET order:lock:userId:game 1 EX 5 NX`，5 秒内同一用户同一游戏只能下单一次。

### Q: 为什么用双 Token（Access + Refresh）？
**A**: Access Token 短 TTL (15m) 减小泄露风险，Refresh Token 长 TTL (7d) 存 Redis，可随时作废。每次 Access 过期后用 Refresh 换新的 Access。

### Q: 密码怎么存的？
**A**: BCrypt 加盐哈希。`BCrypt.hashpw(password, BCrypt.gensalt(12))`。即使数据库泄露，也无法反推密码。

### Q: 前后端怎么解决跨域？
**A**: 开发时 Vite proxy 转发 `/api` 请求到后端。生产环境用 Nginx 反代或后端配置 CORS。

### Q: MyBatis 中 #{} 和 ${} 的区别？
**A**: `#{}`是预编译占位符（防 SQL 注入），`${}`是字符串拼接（只在非用户输入的场景用，如表名、排序字段）。本项目全用 `#{}`。
